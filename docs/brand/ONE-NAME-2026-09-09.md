## ⚠️ ONE SURFACE DELIBERATELY NOT CHANGED — THE LANDING MASTHEAD

The landing page hero is **not a string**. It is a two-part gilded lockup:

```html
<h1 class="wordmark">
  <span class="caps">CAPS</span>     <!-- serif 900, clamp(64px,22vw,104px), gold gradient -->
  <span class="poker">POKER</span>   <!-- serif 600, clamp(15px,5vw,20px), letter-spacing 11px,
                                           text-transform: uppercase -->
</h1>
```

It renders `CAPS POKER` at two very different sizes with a gold gradient on the first word.
Unifying it is not a string edit — it means redesigning the page's central visual identity, and
`POKER` is uppercased by CSS as well as in the source.

**I judged this a logo, not a name, and left it.** All-caps wordmarks are ordinary and do not read
to a player as a second name; the defect Roye was fixing was a player meeting two different names,
and that was the store-versus-device-label mismatch, now closed. **This is his to overrule.** If he
wants it changed it is two edits: `<span class="poker">Poker</span>` and dropping
`text-transform:uppercase` from `.poker` at `public/landing.html:105`.

The same question applies to the icon and splash wordmarks, which were not in scope.

## ⚠️ THREE INSTRUMENT FAILURES IN THIS SPRINT, ALL MINE

1. **The rig pointed at a port with nothing on it.** `tests/serve-dist-like-prod.mjs` **hardcodes
   8899** and ignores any argument; I passed 8931. Every `goto` hung and the run produced no output
   at all. A rig aimed at the wrong port looks exactly like a broken product.
2. **`innerText` applies CSS `text-transform`, and I read that as a stale name.** The first check
   compared `document.body.innerText` and reported the landing page as still saying `CAPS POKER`.
   That would have been a defect filed against a typographic treatment. Spelling is now judged from
   `textContent`; `text-transform` is reported separately as the design choice it is.
3. **AND THE FIX INTRODUCED A BLIND SPOT THAT PRINTED A FALSE GREEN.** The corrected probe scanned
   only leaf elements whose own text matched `/CAPS/i`. The masthead is split across two spans —
   `CAPS` in one, `POKER` in the other — so **neither leaf matched**, and the rig announced
   "every element spells CAPS Poker" while the page painted `CAPS POKER`. Caught only because the
   two rigs disagreed and I chased the disagreement instead of believing the green one. Containers
   are now read by rendered `innerText` as well.

And a fourth, recorded because it is in this project's own notes and I did it anyway: **`pkill -f`
matched its own shell** and killed the command mid-run (exit 144).
