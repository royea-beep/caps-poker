# The explainers, re-checked — and one clip opened on the splash

**Date** 2026-09-07 · `docs/explainers/` · every frame below was looked at, not inferred.

---

## The defect the brief's warning caught

Clip **06-profile** opened on the **CAPS splash screen**, under the caption
"PROFILE — hands, win rate, streak and chips". That is exactly the shape the brief named — a
spinner or splash as the hook — and it shipped in the previous cut.

⚠️ **My previous verification missed it, and the reason matters.** Last pass I built a sheet of
every clip's **final** frame and looked at all eight. Every one was correct. The first frame was
never checked, so a clip that ends right and starts wrong passed a check I had described as
watching every clip. **A verification that only looks at one end is not a verification.**

The cause was my own window change. I had moved profile from 68.0s to 66.0s to avoid this take's
black tail, reading the position off a filmstrip sampled every **3 seconds**. Re-sampled at
**0.5 seconds**, the transition is:

| Time | What is on screen |
| --- | --- |
| 63.0 – 64.5 | hand history |
| **65.0** | a **white** navigation frame |
| **65.5 – 66.0** | the **CAPS splash** ← the old cut started here |
| 66.5 | profile, still painting |
| **67.0 onward** | profile, complete |

**Fixed:** `06-profile` now starts at **67.5s** and runs 9.0s. Verified by looking at it.

## ⚠️ Two guards were built, measured, and thrown away before one worked

Both looked rigorous. Neither separated anything. Recording them so nobody rebuilds them.

**Attempt 1 — "fraction of pixels far from the dominant colour."** The idea: a splash is nearly
uniform, a real screen is busy.

| Frame | Score | |
| --- | --- | --- |
| the splash | 0.169 | |
| 05-hand-history (legitimate) | **0.046** | ← *lower* than the splash |
| 07-lobby (legitimate) | 0.169 | ← *identical* to the splash |

It would have **passed the splash and failed a good clip**.

**Attempt 2 — ffmpeg `signalstats` YUV average difference.** The splash-opening profile frame
scored **3.45**; the legitimate lobby frame scored **3.47**. A global luma average cannot tell a
dark screen from a dark splash.

⚠️ **And attempt 2 hid a second mistake of mine:** I calibrated the threshold with one instrument
(a per-pixel RGB comparison) and enforced it with another (ffmpeg's YUV averages). Different
units, same number. The guard fired on a frame that was fine, and I nearly "fixed" the clip to
satisfy a broken ruler.

**What works is not a statistic — it is an identity check.** The splash is a *known image*.
Compare frame 0 to it per pixel, mean absolute RGB difference at 96×171:

| Clip | Difference from the splash |
| --- | --- |
| **06-profile at 66.0s (the defect)** | **0.00** |
| 08-shop | 5.58 |
| 06-profile at 67.5s (fixed) | 7.64 |
| 07-lobby | 7.95 |
| 05-hand-history | 15.32 |
| 01-home | 19.31 |
| 02 / 03 / 04 | 46.13 – 49.76 |

Floor **3.0**, enforced in `tools/explainer-cut.mjs` with the same code that produced those
numbers. ⚠️ The 0.00 is exact only because the reference frame came from this same take; a splash
from another recording would score slightly above zero, nowhere near 5.58. **The real margin is
the 5.58, and it is stated rather than dressed up.**

**The guard was proven to fire**, not assumed to: putting the 66.0s window back throws

```
Error: 06-profile: HOOK IS THE SPLASH — frame 0 is 1.97 from the splash reference (floor 3)
```

and restoring 67.5s cuts all eight clean.
