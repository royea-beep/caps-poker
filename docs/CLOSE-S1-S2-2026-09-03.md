## S1 — why it is HELD, and the sequence to close it (Roye's ruling, 2026-09-03)

The only server-side change that closes the mint (`auth.uid() IS NULL → false`) is the same change
that refuses the app-open economy calls of any anonymous player whose fire-and-forget sign-in has
not landed. There is no server-only discriminator between "attacker who never signs in" and
"legitimate player mid-startup" — at the moment of the call both are the anon role with
`auth.uid()` NULL. So closing the mint server-only **necessarily** locks out anonymous players.

**Why the hold is affordable now:** the mint prints **play** chips and payments are **off**
(`iap_enabled` false, verified). Today's damage is bounded. Locking out 99.7% of players to close a
fake-money hole is worse than the hole.

**But it must close before payments are enabled, and before the ladder is treated as real.**

**Two-phase sequence (client scope, NOT this session):**
1. **Ship `feat/appopen-auth-gate`** (already BUILT and UNSHIPPED — MEMORY.md:226): the app awaits a
   session (bounded await, J2 pattern — never an unbounded await, or an auth outage becomes a blank
   home screen) **before** its first economy call.
2. **Only after that OTA is in production and verified** — flip `econ_bind_ok` fail-closed:
   `service_role` bypass first (so resolve-hand survives), then `auth.uid() IS NULL → false`, then
   `EXCEPTION WHEN OTHERS → false + log`. Then re-run the three mints raw-anon → all must refuse,
   and every signed-in caller + the resolve-hand path must still pass.

This session's scope is `supabase/ docs/ tests/`; the client OTA is `app/ utils/`, so step 1 is a
separate, client-scoped session. This doc is the standing record so the flip is not lost.

## S2 — the fix, in full

**Root cause.** `tg_hand_history_leaderboard_counters` (AFTER INSERT on `hand_history`,
SECURITY DEFINER) did `UPDATE leaderboard … WHERE device_id = NEW.device_id`, and `device_id` on the
incoming row was never checked against the caller. Two anon-reachable vectors filed a `won` row for
a victim device:
- **A — direct table insert.** RLS `users_own_hh` is `auth.uid() = user_id` (checks user_id, not
  device_id). An anonymous session inserts `{user_id: own, device_id: victim, session_type:
  'quick_poker', result: 'won'}` → the row passes RLS → the trigger climbs the victim's rank.
- **B — `record_hand_result_d` RPC.** SECURITY DEFINER, `EXECUTE` granted to **anon**, reads
  `user_id` from `push_tokens` (not the caller) and inserts for **any** `p_device_id` with **no
  ownership check**. `record_hand_result_d(p_device_id => victim, p_won => true, p_session_type =>
  'quick_poker')` → same climb, callable with no session at all.

**Why a client-vs-server discriminator is available and race-free.** The two legitimate writers are
(1) `record_hand_result_d` (SECURITY DEFINER, owner postgres) for the caller's own solo/practice
row, and (2) the **resolve-hand** edge function (service_role REST) for every multiplayer seat
incl. a seat that dropped. Inside the SECURITY DEFINER trigger, `current_user` is always the trigger
owner (unusable), but **`auth.role()`** reads `request.jwt.claims` — set per request by PostgREST
and unchanged by SECURITY DEFINER — and returns `service_role` only for the resolve-hand writer.
A client (direct insert or the RPC) always carries an anon/authenticated JWT. No `device_identity`
binding and no auth-timing are involved, so — unlike S1 — this fix has **no anonymous-lockout risk.**

**The fix.** One guard at the top of the trigger:
```sql
IF auth.role() IS DISTINCT FROM 'service_role' THEN RETURN NULL; END IF;
```
The ladder (elo / games_played / wins / win_rate) now moves **only** for the service-role writer.
Every client row still records to `hand_history` (personal history, win_rate, hands unaffected) but
moves no ladder — so a forged row for a victim device climbs nothing.

**Deliberate consequence (approved).** Solo-vs-bots (`quick_poker`) no longer moves the competitive
ladder — the same reason practice already never did (beating a bot risks nothing competitively). The
lobby is empty (0 multiplayer rooms have ever finished; live `hand_history` is 53 `quick_poker` + 23
`practice`, no `multiplayer` rows yet), so no device currently climbs until real multiplayer exists.
Accepted: a ladder anyone can forge, or one earned against bots, is not a ladder.

**Applied.** Migration `supabase/migrations/20260903000000_close_s2_ladder_forge_server_authoritative.sql`
(recorded via `apply_migration`; deployed function verified to carry the guard and to keep the
practice exclusion). Branch `close-s2-ladder` deleted after proof.
