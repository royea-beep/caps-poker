## The victim is still real, for a completely different reason

The public link installs nothing today, and expiry has nothing to do with it. This is the line
that matters, from the same run:

```
  externalBuildState       READY_FOR_BETA_SUBMISSION
```

Apple **withholds a build from external testers until Beta App Review passes**, no matter how many
groups it is attached to. Attachment is not delivery. So a stranger clicking the public link still
sees "No TestFlight builds are available for this app" — not because the build is old, but because
it has never been submitted for review.

## The shortest path: one workflow dispatch, no rebuild

**Nothing needs rebuilding and no binary needs re-uploading.** 515 is valid, unexpired, compliant
and already attached to the external group. The only missing act is the review submission, and the
repo already has it behind a deliberate switch:

> **Actions → Manage TestFlight → Run workflow**
> `action: distribute` · `submit_beta_review: true`

That creates the `betaAppReviewSubmission` (`tools/asc/ensure_distribution.rb`, which currently
prints "an EXTERNAL group was touched and SUBMIT_BETA_REVIEW is not true"). It is opt-in precisely
because a review is a real wait that can be rejected.

**How long.** Apple's own queue, and I cannot see it. Beta App Review is commonly under a day or
two, and the FIRST external submission for an app is the slow one — later builds of the same
version usually skip re-review. Treat any number tighter than "a day or two, not guaranteed" as
invented.

**What could block it.** Rejection, and two things on this app make that non-trivial rather than a
formality:
1. **The 18+ simulated-gambling rating.** A reviewer has to be satisfied there is no real money.
   The app's own copy says so ("No real money. No gambling. Virtual chips only."), which helps.
2. **Beta App Review information must be complete in App Store Connect** — description, contact,
   and notes. The reviewer notes in `APPSTORE_METADATA.md` mention local WiFi multiplayer, which a
   reviewer may try to exercise.

## The same-day alternative, with no review at all

`internalBuildState: IN_BETA_TESTING` and "Internal Testers" already serves 515. **Internal testers
install immediately, with no Beta App Review.** The cost is that Apple only serves internal builds
to App Store Connect **users** on the team, so each person has to be added to the account — fine
for a handful of friends, not for a public link.

So there are two real answers depending on the audience: a public link needs the review, and a
short trusted list does not need to wait for anything.
