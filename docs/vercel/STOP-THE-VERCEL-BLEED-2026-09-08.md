## §2 · THE CAUSE, READ OUT OF THE RECORD RATHER THAN GUESSED

The failing deploys do not have build logs. `get_deployment_build_logs` returns
**"No build log events found"** for every one of them — because no build ever started. The reason
is one field on the deployment object itself:

```
"errorMessage": "The `vercel.json` schema validation failed with the following message:
                 should NOT have additional property `_comment_rewrites`"
```

Identical on the **newest** failure (`dpl_9n8iqExq…`, 07:42 UTC today) and on the **oldest one in
the window** (`dpl_2tx2cDqJ…`). Not a Root Directory problem. Not an Output Directory problem. Not
the build command. **A property name.**

### `vercel.json` is JSON, and JSON has no comments

On 2026-09-03, commit `ae2e731` — the same commit that put the catch-all 404 fix into the file
production never reads — added a `_comment_rewrites` array to the **root** `vercel.json` to explain
the change. JSON has no comment syntax, so that is a real property. Vercel validates `vercel.json`
against a **closed schema**, and it does so **before** it runs the project's Ignored Build Step.

So the sequence is: *validate → ignore-step → build*. The comment kills it at step one, and the
skip that had been working for weeks never gets to run.

### The control case that proves the mechanism

One deploy in the window was CANCELED rather than ERROR while every sibling errored:
`dpl_CPnv5G65…`, commit `615107e` on branch `claude/caps-001-audit`. That branch **does not contain
`ae2e731`** (`git merge-base --is-ancestor` says so), so its `vercel.json` has no comment key — and
it skipped cleanly. Same project, same settings, same day. The only variable is the property.

### What `gitRootDirectory=dist` actually means — confirmed, not inferred

The brief flagged it as a clue. It is one, and it is **not** the fault:

* `.github/workflows/web-deploy.yml` builds with `expo export --output-dir dist`, runs
  `scripts/fix-web-html.js`, then runs `npx vercel --prod --yes` with `working-directory: dist`.
* `fix-web-html.js:141` writes `dist/.vercel/project.json` pinning that same project and org id.
* So the READY rows are **CLI deploys of a pre-built directory**, and `dist` is simply the directory
  the CLI was invoked from. `gitDirty: 1` on every one of them says the same thing.

`dist/vercel.json` is generated by `JSON.stringify` from an object literal, so **it never carried
the comment** — which is exactly why production kept deploying green while every Git deploy went red.

### Therefore: the red deploys are free, and the green ones are not

`buildingAt == ready == createdAt`, to the millisecond, on every ERROR and every CANCELED row. No
container is allocated. **29 failed deploys consumed no build compute.**

The 8 READY rows did run. And **5 of those 8 were pushes whose entire diff was documentation** —
`docs(build-515)`, `docs(testflight)`, `docs(finish-hebrew)`, and so on. Each one ran a full
`expo export`, `npx playwright install --with-deps chromium`, a WCAG audit, BackstopJS, and a
production deploy, to publish a bundle byte-identical to the one already live.

**That is the compute this project is actually paying for.** The scary red column is noise; the
quiet green column is the bill.

## §3 · WHAT CHANGED

**One commit, everything in it — see §4.**

1. **`vercel.json` — `_comment_rewrites` deleted.** Twelve lines, no behaviour. The prose it
   contained was already duplicated, word for word, in `scripts/fix-web-html.js`, which is
   JavaScript and can hold a real comment. Nothing was lost.
   ⚠️ **The rewrites and headers are untouched.** Same catch-all, same four rules, same four
   security headers. `tests/vercel-rewrites.test.ts`'s 50 existing assertions still pass unchanged.

2. **`tests/vercel-rewrites.test.ts` — a guard, proven to fire.** Two new cases: no top-level key
   outside Vercel's documented set, and none beginning with `_`; plus one asserting the generator
   has not grown a `_comment` *property*. **Proved by putting the defect back**: with
   `_comment_rewrites` restored the suite fails and names the key in the diff. Restored after.

3. **`.github/workflows/web-deploy.yml` — `paths-ignore: ['docs/**', '**/*.md']`.**
   This is the change that saves money, because it is on the path that actually spends it.
   ⚠️ **Deliberately narrow, and verified rather than assumed.** `expo export` copies `public/`
   into `dist/`, and `fix-web-html.js` then copies the ROOT `privacy.html` and `terms.html` over
   the top. `docs/` is referenced by neither; no source file imports from `docs/` or from any `.md`;
   `public/` contains no `.md`. Nothing on the list can change a served byte. Everything that can —
   `app/`, `components/`, `public/`, `privacy.html`, `terms.html`, `scripts/`, `package.json`,
   `assets/` — still deploys on every push. `paths-ignore` skips only when *every* changed file
   matches, so a commit that bundles docs with its code still deploys. `workflow_dispatch` stays as
   the escape hatch.

**Nothing was disabled and no Git integration was disconnected.** The brief offered those as
fallbacks if the fix did not land. It landed, and the project's own Ignored Build Step already
provides that protection — turning it off as well would have removed a working control to fix a
problem it was never the cause of.
