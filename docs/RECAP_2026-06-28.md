## The method that worked: 3-layer independent verification
- **Layer 1 (DB sim):** strategist called the real RPCs in user-sequence against the live DB,
  stashed jsonb results into marker rows, asserted the tables, cleaned up, proved 0 residue. This
  FOUND the seat-collision 500 and the club-gate hole — both passed tsc + tests.
- **Layer 2 (web visual):** builder used claude-in-chrome + Vercel preview deploys, 2 isolated browser
  contexts (separate localStorage → 2 anon users) for real 2-client games, screenshots at 320+390.
- **Layer 3 (native):** human on-device after OTA (automation = the open QA-pipeline task; Maestro chosen).

## Key learnings (portable to all projects)
- **DB ground-truth beats reports.** Caught the track_event false-alarm (twice), the "0 clubs"
  misread, the crash-wording nuance, and 2 real bugs — all by reading tables, not trusting "DONE".
- **Static proof ≠ live proof.** "strings present in bundle" / "tsc passes" repeatedly looked fine while
  something visual or runtime differed. Always watch it actually run.
- **Refuse to claim unverified.** When BoardReveal couldn't be captured in 2-client, it shipped behind
  an OFF flag rather than claimed working. That discipline is the goal.
- **Coordinate activation with the client.** Backend (lobby pool, ghost-evict cron) was built but NOT
  activated until the client shipped the matching code (heartbeat) — else it would break/evict wrongly.
- **Guard new logic so it can't break live clients.** Every change was gated (is_public / club_id /
  feature flag) so existing behavior was untouched until intended.
